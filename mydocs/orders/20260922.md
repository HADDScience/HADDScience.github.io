## 합친 방법

두 덱을 이어 붙이면 표지가 두 장이 되고 같은 사실이 두 번 나온다. 그래서 **한 편으로 다시 썼다** —
RISE 덱 14장(표지 + 글만 카드 13장, 사진 2장뿐이고 한 챕터를 두 장씩 나눠 씀) + 위촉 덱 8장을
**13장**으로. 내용은 버리지 않았다:

- 위촉 덱의 사진 다섯(위촉장 수여 · 단체사진 · 위촉장 · 위촉위원 배치도 · 부총장과 기념사진)을 전부 쓴다
- RISE 덱에서 두 장으로 나뉘어 있던 것(RISE 설명 / 살기 좋은 화성 + 직·주·락 / 애드젤 / 기술 셰르파)을
  각각 한 장으로 합쳤다
- 어조는 위촉 덱 쪽(사실 중심)에 맞췄다

순서: 위촉(2026.01.29) → 발대식 → 위촉장 문구 → 위원회가 하는 일 → 위원 구성 → RISE 란 → 인재가 남는 구조
→ 연구실에서 지역으로 → 애드젤 → 클러스터의 기술 엔진 → 기술 셰르파 → 맺음 인용.

제목은 그대로 뒀다(대표님이 제목은 말씀하지 않으셨다). 비어 있던 요약만 한 줄 채웠다.

## 반영 경로 — API 를 못 쓰고 DB·NAS 에 직접 썼다

관리 화면(`/admin`)의 저장은 브라우저가 덱을 굽고 Omnis API 에 올리는 길인데, 그 API 는 SSO 세션을 요구한다.
`vercel env pull` 이 받아 온 `.env.vercel` 에서 `SSO_SIGNING_KEY` · `SYNOLOGY_WEBDAV_*` 는 **[SENSITIVE] 로
가려져** 있어 토큰을 만들 수 없었다. `DATABASE_URL` 은 가려져 있지 않고 NAS 는 로컬에 마운트돼 있어
(`hadd on /Users/jeong-uchang/NAS (macfuse)`) 그쪽으로 갔다.

- 카드 굽기: `https://haddscience.com/admin/lint` 의 `window.__cardnews` 브리지를 Playwright 로 불렀다.
  이 화면이 관리 화면과 같은 `CardFace` · 같은 `html-to-image` 를 쓰므로 편집기로 저장한 것과 같은 그림이 나온다.
- 조판 검사(`lintCard`): 한글·영문 각 13장 **고아 줄 0건**. 처음엔 한글 표지 1건, 영문 5건이 걸려 문구를 고쳤다.
- 영문은 자동 번역 API(`/translate`) 대신 직접 썼다. `translatedFrom` 은 원문 해시(`sourceHash`)를 같은 방식으로
  계산해 넣었으므로, 나중에 관리 화면에서 저장해도 다시 번역되지 않는다.

`REVALIDATE_SECRET` 도 가려져 있어 즉시 재검증은 부르지 못했다. 60초 ISR 로 따라왔다.

## 기사 고정(HADD PICK)

오전에 「앞으로 빼 달라」는 요청을 `position` 을 0 으로 옮겨 처리했는데, 그러면 **왜 거기 있는지가
화면에 드러나지 않는다** — 날짜 순서만 깨진 것처럼 보인다. 고정을 상태로 따로 둔다.

계획서는 Omnis 쪽에 있다: `omnis/mydocs/plans/archives/2026-09-22-website-post-pin.md`
(스키마·API 가 그쪽에서 바뀌므로 AGENTS.md 의 "Omnis 와 함께 바뀌는 작업" 규칙을 따랐다).

작업지시자가 정한 것: 카드 크기는 그대로 두고 **브랜드 블루 2px 테두리 + `shadow-ds-brand` + 배지**,
배지 문구는 한·영 모두 `HADD PICK`, 개수 제한 없음, 뉴스·하드:라이브러리 둘 다.

이 저장소에서 바뀐 것:

| 파일 | 무엇 |
|---|---|
| `content/types.ts` | `Post.pinned` · `NewsItem.pinned` · `ui.pinned` |
| `content/server.ts` | DTO 에서 받는다. **없으면 `false`** — 사이트가 Omnis 보다 먼저 나가도 깨지지 않는다 |
| `content/{ko,en}.ts` | `ui.pinned = "HADD PICK"` (브랜드 표기라 번역하지 않는다) |
| `components/ds/primitives.tsx` | `Badge` 에 `brand` 톤. 사진 위에 얹히므로 채운 색이어야 읽힌다 |
| `components/ds/cards.tsx` | 카드형은 사진 왼쪽 위 배지 + 테두리, 줄형(홈)은 날짜 옆 배지 |
| `lib/admin-posts.ts` | `setPinned()` — `PUT /posts/<id>/pin` |
| `app/admin/page.tsx` | 줄마다 압정 토글 · 고정 줄 테두리 강조 · 목록에도 배지 |

정렬은 사이트에서 하지 않는다. Omnis 가 `[pinned desc, position asc, id desc]` 로 내려보내고 그대로 그린다.
`position` 을 건드리지 않으므로 **고정을 풀면 원래 자리로 돌아간다** — 오전처럼 순서를 옮겼으면 이 되돌리기가 없다.

압정은 기사 전체를 PUT 하지 않고 전용 경로를 쓴다. 본문·덱을 다시 쓰고 번역 검사까지 도는 것을 피하고,
화면이 들고 있던 옛 본문으로 남의 수정을 덮는 일도 막는다.

## 로그인 버튼 없이 들어오기

관리 화면 세션(`localStorage`, 8시간)과 옴니스 로그인(`omnis.haddscience.com` 쿠키)은 **다른 오리진**이라
여기서 저쪽이 살아 있는지 읽을 수 없다. 확인하는 유일한 방법이 `/sso/authorize` 로 한 번 다녀오는 것이고,
버튼이 하던 일이 정확히 그거였다. 그래서 그냥 다녀온다(`hooks/use-admin-session.ts`).

무한 왕복을 막는 장치: `sessionStorage` 의 `hadd.sso.auto-signin` 으로 **탭당 한 번**만 시도한다.
로그인에 성공하면 표식을 풀어 8시간 뒤 만료됐을 때 다시 한 번 조용히 다녀올 수 있게 하고,
**「나가기」를 누르면 표식을 남겨** 곧바로 다시 들어와지지 않게 한다.

옴니스의 `/sso/authorize` 는 세 갈래로만 끝난다 — 오류 HTML, 옴니스 로그인 화면, 표를 달고 복귀.
표 없이 되돌려보내는 길이 없어서 왕복이 스스로 이어지지는 않는다. 그래도 표식은 남긴다.

## 사이트 방문 통계 (2026-09-22)

"어느 정도의 사용자가 방문했는지 admin 에서 보고 싶다"는 요청. 먼저 확인한 것은 **지금까지
아무것도 모으고 있지 않았다**는 사실이다 — `@vercel/analytics` 도 GA 도 없고 Vercel Web
Analytics 도 프로젝트에서 꺼져 있었다(`web_analytics_not_enabled`). 그래서 어떤 도구를 붙이든
숫자는 켜는 날부터다. 지난 방문은 복원할 수 없다.

Vercel Web Analytics 대신 **Omnis 에 직접 쌓기**를 골랐다(작업지시자 선택). 조회용 토큰을
들고 다닐 필요가 없고 보존 기간을 플랜이 아니라 우리가 정한다.
**설계의 정본은 Omnis 의 `mydocs/plans/2026-09-22-website-visit-stats.md`** — 스키마와
엔드포인트가 다르면 그쪽을 따른다. 이 저장소가 맡은 것은 비콘 · 전달 · 표시다.

쿠키를 쓰지 않는다. 방문자 구분은 `HMAC(비밀, KST날짜+IP+UA)` 앞 16바이트이고 IP·UA 는
`/api/hit` 에서 쓰고 버린다(Omnis 로 가지 않는다). 동의 배너가 필요 없는 대신, 날이 바뀌면
같은 사람이 다시 세어지고 폰과 PC 는 2명이다.

```
질의문자 제거: /en/products?utm=x#top → /en/products, referrer=google.com, device=mobile
```

Omnis 라우트 직접 호출: 비밀 없음 503 · 비밀 없이 401 · 틀린 비밀 401 · 본문 이상 400 ·
해시 형식 위반 400 · 정상 202 + DB 1행.

집계 질의(로컬 DB): 오늘 5건·사흘 전 2건 → 합계 `{views:7, visitors:4}` · 오늘 `{5,3}`.
**기간 방문자가 일별 합(3+1)이 아니라 서로 다른 해시 수로 나온다.** 빈 날 0 채움, KST 경계,
인기 경로·유입·기기 집계까지 확인.

관리 화면(목킹 30일치): 타일 4 · 일별 막대 30칸 · 기간 토글 7↔30↔90 재조회 ·
경로가 글 제목으로 치환 · 가로 넘침 없음.

### 남은 것

- `WEBSITE_VISIT_SECRET` 을 Omnis·사이트 양쪽 Vercel 환경변수에 같은 값으로 넣어야 한다.
  **없으면 집계가 조용히 멈춘다**(화면은 멀쩡하다).
- Omnis 운영 DB 에 마이그레이션을 먼저 적용하고 그 다음 머지한다.

## 글별 방문 수 (2026-09-22)

"콘텐츠별로 얼마나 방문했는지"까지 요청. 통계 패널의 인기 페이지 상위 10개로는 모자란다 —
목록의 글 하나하나에 숫자가 붙어야 관리하면서 바로 읽힌다.

Omnis 의 `/api/website/stats` 응답에 `posts`(글별 조회·방문자)를 더했다. **한국어판과 영문판을
한 글로 합쳐 센다** — 목록이 글 하나를 한 줄로 보여 주므로 언어별로 나누면 붙일 자리가 없다.
주소에서 id 만 떼되 글 주소 모양(`^/(ko|en)/(news|library)/[^/]+$`)만 세므로, 목록 `/ko/news` 와
쪽나누기 `/ko/news/page/3` 는 섞이지 않는다.

사이트 쪽은 통계를 **한 벌만 받아** 패널과 목록이 같이 쓰도록 `useVisitStats` 훅으로 올렸다.
따로 받으면 기간이 어긋난다(패널 7일 · 목록 30일).

정렬은 화면에서만이다. `position` 을 건드리지 않으므로 사이트 순서와 고정은 그대로다.

### 실측

```
Omnis(로컬 DB)  한 글에 한국어 3회(2명) + 영문 2회(1명) → {views:5, visitors:3} 한 줄
                같은 데이터의 /ko · /ko/news · /ko/news/page/3 · /en/products 는 글별에서 빠짐
관리 화면(목킹)  줄마다 96회 · 12회 · –(방문 없음) · 40회
                "많이 본 순" → 96 · 40 · 12 · – 로 재정렬, aria-pressed 이동
                줄 구성: 썸네일 · 제목 · [96회] · 고정 · 사이트에서 보기 · 삭제
품질 게이트      typecheck · lint · build(361/361) 통과
```

## 관리 화면을 둘로 나눔 (2026-09-22)

"통계 보여주는 페이지랑 컨텐츠 추가하는 페이지로 구분해 달라"는 요청. 한 화면에 다 있으니
글 하나 고치러 들어와도 통계부터 읽고 내려와야 했다.

```
/admin         콘텐츠   목록 · 검색 · 새 글 · 편집기 · 줄마다 조회 수 · 정렬
/admin/stats   통계     사이트 방문 + 콘텐츠 현황(재고 · 손볼 것)
```

`components/admin/shell.tsx` 가 로그인 관문과 머리·전환을 한 번만 다룬다. 페이지마다
상태 셋(loading·anonymous·ready)을 되풀이하면 한쪽만 고치는 일이 생긴다.

**글별 조회 수는 콘텐츠 쪽에 남겼다.** 그건 그 글에 대한 정보라 관리하면서 같이 보는 편이 낫다.
반대로 **"손볼 것" 은 통계 쪽으로 보내되, 누르면 콘텐츠 화면으로 주소를 달고 넘어가게** 했다
(`/admin?issue=no-body&tab=news`) — 고칠 글은 고치는 화면에서 열어야 한다. 주소에 남으니
"번역 없는 글 목록"을 북마크하거나 남에게 보낼 수도 있다. 필터가 걸린 동안에는 목록 위에
무엇을 보고 있는지와 **전체 보기** 를 띄운다.

### 실측 (목킹 데이터, dev)

```
/admin        제목 "콘텐츠 관리" · nav [콘텐츠*][통계] · 통계 패널 0개 · 목록 3건
/admin/stats  제목 "사이트 통계" · nav [콘텐츠][통계*] · 패널 "사이트 통계" + "콘텐츠 현황"
칩 "번역 없음" 클릭
  → /admin?issue=untranslated&tab=news
  → "번역 없음인 글만 보고 있습니다 (1건) · 전체 보기"
  → 목록에 「번역이 없는 뉴스」 한 건만
품질 게이트  typecheck · lint · build(362/362, /admin/stats 라우트 생성) 통과
```

사용법 문서에서 **절 번호가 겹쳐** 있었다(다른 세션의 「기사 고정하기」와 내 「콘텐츠 현황」이
둘 다 2-4). 뒤엣것을 2-5 로 밀었다.
