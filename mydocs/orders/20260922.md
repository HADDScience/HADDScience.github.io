## 합친 방법

두 덱을 이어 붙이면 표지가 두 장이 되고 같은 사실이 두 번 나온다. 그래서 **한 편으로 다시 썼다** —
RISE 덱 14장(표지 + 글만 카드 13장, 사진 2장뿐이고 한 챕터를 두 장씩 나눠 씀) + 위촉 덱 8장을
**13장**으로. 내용은 버리지 않았다:

- 위촉 덱의 사진 다섯(위촉장 수여 · 단체사진 · 위촉장 · 위촉위원 배치도 · 부총장과 기념사진)을 전부 쓴다
- RISE 덱에서 두 장으로 나뉘어 있던 것(RISE 설명 / 살기 좋은 화성 + 직·주·락 / 애드젤 / 기술 셰르파)을
  각각 한 장으로 합쳤다
- 어조는 위촉 덱 쪽(사실 중심)에 맞췄다

순서: 위촉(2026.01.29) → 발대식 → 위촉장 문구 → 위원회가 하는 일 → 위원 구성 → RISE 란 → 인재가 남는 구조
→ 연구실에서 지역으로 → 애드젤 → 클러스터의 기술 엔진 → 기술 셰르파 → 맺음 인용.

제목은 그대로 뒀다(대표님이 제목은 말씀하지 않으셨다). 비어 있던 요약만 한 줄 채웠다.

## 반영 경로 — API 를 못 쓰고 DB·NAS 에 직접 썼다

관리 화면(`/admin`)의 저장은 브라우저가 덱을 굽고 Omnis API 에 올리는 길인데, 그 API 는 SSO 세션을 요구한다.
`vercel env pull` 이 받아 온 `.env.vercel` 에서 `SSO_SIGNING_KEY` · `SYNOLOGY_WEBDAV_*` 는 **[SENSITIVE] 로
가려져** 있어 토큰을 만들 수 없었다. `DATABASE_URL` 은 가려져 있지 않고 NAS 는 로컬에 마운트돼 있어
(`hadd on /Users/jeong-uchang/NAS (macfuse)`) 그쪽으로 갔다.

- 카드 굽기: `https://haddscience.com/admin/lint` 의 `window.__cardnews` 브리지를 Playwright 로 불렀다.
  이 화면이 관리 화면과 같은 `CardFace` · 같은 `html-to-image` 를 쓰므로 편집기로 저장한 것과 같은 그림이 나온다.
- 조판 검사(`lintCard`): 한글·영문 각 13장 **고아 줄 0건**. 처음엔 한글 표지 1건, 영문 5건이 걸려 문구를 고쳤다.
- 영문은 자동 번역 API(`/translate`) 대신 직접 썼다. `translatedFrom` 은 원문 해시(`sourceHash`)를 같은 방식으로
  계산해 넣었으므로, 나중에 관리 화면에서 저장해도 다시 번역되지 않는다.

`REVALIDATE_SECRET` 도 가려져 있어 즉시 재검증은 부르지 못했다. 60초 ISR 로 따라왔다.

## 기사 고정(HADD PICK)

오전에 「앞으로 빼 달라」는 요청을 `position` 을 0 으로 옮겨 처리했는데, 그러면 **왜 거기 있는지가
화면에 드러나지 않는다** — 날짜 순서만 깨진 것처럼 보인다. 고정을 상태로 따로 둔다.

계획서는 Omnis 쪽에 있다: `omnis/mydocs/plans/2026-09-22-website-post-pin.md`
(스키마·API 가 그쪽에서 바뀌므로 AGENTS.md 의 "Omnis 와 함께 바뀌는 작업" 규칙을 따랐다).

작업지시자가 정한 것: 카드 크기는 그대로 두고 **브랜드 블루 2px 테두리 + `shadow-ds-brand` + 배지**,
배지 문구는 한·영 모두 `HADD PICK`, 개수 제한 없음, 뉴스·하드:라이브러리 둘 다.

이 저장소에서 바뀐 것:

| 파일 | 무엇 |
|---|---|
| `content/types.ts` | `Post.pinned` · `NewsItem.pinned` · `ui.pinned` |
| `content/server.ts` | DTO 에서 받는다. **없으면 `false`** — 사이트가 Omnis 보다 먼저 나가도 깨지지 않는다 |
| `content/{ko,en}.ts` | `ui.pinned = "HADD PICK"` (브랜드 표기라 번역하지 않는다) |
| `components/ds/primitives.tsx` | `Badge` 에 `brand` 톤. 사진 위에 얹히므로 채운 색이어야 읽힌다 |
| `components/ds/cards.tsx` | 카드형은 사진 왼쪽 위 배지 + 테두리, 줄형(홈)은 날짜 옆 배지 |
| `lib/admin-posts.ts` | `setPinned()` — `PUT /posts/<id>/pin` |
| `app/admin/page.tsx` | 줄마다 압정 토글 · 고정 줄 테두리 강조 · 목록에도 배지 |

정렬은 사이트에서 하지 않는다. Omnis 가 `[pinned desc, position asc, id desc]` 로 내려보내고 그대로 그린다.
`position` 을 건드리지 않으므로 **고정을 풀면 원래 자리로 돌아간다** — 오전처럼 순서를 옮겼으면 이 되돌리기가 없다.

압정은 기사 전체를 PUT 하지 않고 전용 경로를 쓴다. 본문·덱을 다시 쓰고 번역 검사까지 도는 것을 피하고,
화면이 들고 있던 옛 본문으로 남의 수정을 덮는 일도 막는다.

## 로그인 버튼 없이 들어오기

관리 화면 세션(`localStorage`, 8시간)과 옴니스 로그인(`omnis.haddscience.com` 쿠키)은 **다른 오리진**이라
여기서 저쪽이 살아 있는지 읽을 수 없다. 확인하는 유일한 방법이 `/sso/authorize` 로 한 번 다녀오는 것이고,
버튼이 하던 일이 정확히 그거였다. 그래서 그냥 다녀온다(`hooks/use-admin-session.ts`).

무한 왕복을 막는 장치: `sessionStorage` 의 `hadd.sso.auto-signin` 으로 **탭당 한 번**만 시도한다.
로그인에 성공하면 표식을 풀어 8시간 뒤 만료됐을 때 다시 한 번 조용히 다녀올 수 있게 하고,
**「나가기」를 누르면 표식을 남겨** 곧바로 다시 들어와지지 않게 한다.

옴니스의 `/sso/authorize` 는 세 갈래로만 끝난다 — 오류 HTML, 옴니스 로그인 화면, 표를 달고 복귀.
표 없이 되돌려보내는 길이 없어서 왕복이 스스로 이어지지는 않는다. 그래도 표식은 남긴다.
