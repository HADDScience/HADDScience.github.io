# 2026-09-21 — 관리 화면 콘텐츠 현황 패널 · 작업 결과

## 고른 것과 버린 것

| 결정 | 왜 | 버린 쪽 |
|---|---|---|
| 숫자는 이미 받아 둔 목록에서 센다 | 화면의 목록과 다른 수가 나오는 것이 통계가 없는 것보다 나쁘다. 154건은 브라우저에서 세도 티가 나지 않는다 | Omnis 에 집계 API 를 새로 두는 것 |
| "손볼 것"은 필터다 | 할 일이 몇 건인지만 알려 주고 그 글을 찾는 일은 사람에게 떠넘기면 숫자를 보여 준 보람이 없다 | 숫자만 보여 주는 배지 |
| 결함 정의는 `matchesIssue()` 한 곳 | 패널의 숫자와 목록 필터가 어긋나면 어느 쪽도 못 믿는다 | 패널과 목록이 각자 세기 |
| 본문 없는 글은 번역·요약에서 뺀다 | 한 글이 칩 셋에 동시에 잡히면 무엇부터 하면 되는지가 사라진다 | 조건을 문자 그대로 적용 |
| 탭을 옮기면 칩 필터 해제 | 결함 수가 탭마다 다르다. 0건인 필터가 켜진 채 넘어가면 빈 목록만 보인다 | 필터 유지 |
| 막대는 한 색·범례 없음 | 한 갈래뿐인 값에 색을 나누면 없는 구분이 있는 것처럼 보인다 | 색으로 구분한 막대 |
| 값은 hover 로 | 12개 숫자를 다 적으면 읽히지 않는다. 글이 없는 달은 2px 눈금으로 자리만 지킨다 | 막대마다 숫자 표기 |

한글 라벨에는 `font-mono` + `tracking-[0.12em] uppercase` 를 쓰지 않았다. 처음엔 화면의
다른 라벨을 따라 썼는데 한글이 자간만 벌어지고 서체는 폴백으로 떨어져 읽기 나빴다.
숫자·날짜만 `tabular-nums` 로 둔다.

막대는 칸을 꽉 채우지 않고 폭을 `max-w-9` 로 묶어 가운데 세운다. 12칸을 가득 채우면
기둥이 아니라 벽으로 보인다.

## 실측

목킹 데이터(라이브러리 21 · 뉴스 2, 그 안에 번역 없음 2 · 본문 없음 1 · 썸네일 없음 1 ·
요약 없음 1 · 카드뉴스 4)로 dev 서버에서 쟀다.

```
타일      하드:라이브러리 21건 / 전체 23건
          카드뉴스 4건 · 카드 12장
          번역 있음 19 / 21  (90%)
          최근 12개월 20건 · 마지막 글 2026.09.02   ← 12개월 밖(2024.05.05) 1건 제외됨
칩        번역 없음 2 → 목록이 그 2건만 남음, aria-pressed 켜짐
          0건 칩(본문 없음 · 썸네일 없음 · 요약 없음, 뉴스 탭)은 disabled
탭 전환   라이브러리 → 뉴스 로 옮기면 칩 필터 해제됨
막대      9번째 칸 hover → 툴팁 "2026-06 · 2건", opacity 1
390px     가로 넘침 없음 (scrollWidth 375 ≤ 뷰포트), 타일 1열로 접힘
```

품질 게이트 `pnpm typecheck && pnpm lint && pnpm build` — exit 0, 정적 363쪽 생성.

## 남은 것

- **실제 데이터로는 아직 못 봤다.** 위 숫자는 전부 목킹이다. 실계정으로 열면 라이브러리
  103건의 "손볼 것"이 몇 건인지 처음 드러난다.
- 패널이 늘 펼쳐져 있다. 목록을 바로 보고 싶을 때 접는 수단은 두지 않았다.
- 월별 막대는 `Post.date`(표시용 문자열)를 `YYYY.MM` 으로 읽는다. 형식이 다른 글은
  어느 달에도 세지 않는다 — 지금 데이터에는 없지만 조용히 빠지는 자리다.
