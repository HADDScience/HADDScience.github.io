# 2026-09-28 — 카드뉴스를 구운 이미지가 아니라 HTML 로 그린다

작업지시 (정우창, 2026-09-28): "이미지를 구워서 올리는게 아니라 원본을 올리는건?" → 검토 결과를
보고한 뒤 "진행해줘".

## 문제

본문에 글자가 하나도 없는 글이 **153건 중 37건**이다(2026-09-28 Omnis API 실측: `content.ko.blocks`
에 text · heading · quote 블록이 없다). 전부 카드뉴스다. 카드 안의 글이 PNG/webp 로 구워져 있어
검색엔진은 이미지 alt 만 읽고, 스크린리더도 alt 에 기댄다. 「오가노이드」·「생체소재」로 걸릴 문서를
늘리는 데 가장 큰 구멍이다.

그런데 그중 **35건은 카드 원본(`post.deck`)이 DB 에 있다.** 편집기는 이 원본을 `CardFace` 로 화면에
그린 뒤 그 DOM 을 이미지로 굽는다. 기사 페이지는 원본을 쓰지 않고 구운 결과만 보여 준다. 굽기 전
단계의 DOM 을 그대로 보여 주면 글자가 본문이 된다. 덱의 카드 글은 글마다 중앙값 약 970자다.

## 실측 — 원본과 구운 이미지가 맞물리는가

| | 건수 |
|---|---|
| 덱이 있는 글 | 35 (전부 `sourceLang: ko`) |
| 이미지 블록 수 = 카드 수 | **35** |
| 그중 블록이 카드 이미지뿐 | 21 |
| 카드 이미지 뒤에 `links` 블록이 하나 더 | 14 |
| 덱 없이 구운 이미지뿐 | 2 (라이브러리) — 이 작업으로 해결되지 않는다 |

즉 **k 번째 이미지 블록 = k 번째 카드**다. 링크 블록은 그 사이에 끼지 않고 끝에 붙는다.

## 결정

| 결정 | 선택 | 버린 안 |
|---|---|---|
| 무엇을 그리나 | 덱이 있고 이미지 블록 수가 카드 수와 같으면 **k 번째 이미지 블록 자리에 k 번째 카드를 HTML 로** | 이미지 블록을 통째로 덱으로 교체 — 링크 블록의 위치가 흔들린다 |
| 수가 안 맞으면 | 지금처럼 구운 이미지 | 덱을 우선 — 편집 도중 어긋난 글이 엉뚱한 카드를 보여 준다 |
| 어느 언어 페이지 | **원문 언어(`sourceLang`) 페이지만.** 영문 페이지는 지금처럼 **영문으로 구운 카드**(`-en-NN.webp`) + 영문 alt | 영문 페이지에도 덱 — 한글 카드 글이 영문 페이지 본문에 들어가 영문 alt(번역본)보다 나빠진다 |
| 크기 맞추기 | 1080 고정 카드를 `transform: scale()` 로 줄인다(편집기 `CardPreview` 와 같은 방식). 폭은 `ResizeObserver` 로 재고, 하이드레이션 전에는 화면 폭 구간별 기본값을 CSS 로 준다 | 카드 CSS 를 `cqw` 단위로 다시 쓰기 — 486줄이고 구운 결과와 픽셀이 어긋난다. SVG `foreignObject` — 사파리에서 절대 위치 요소가 어긋나는 버그가 있다 |
| 사진 불러오기 | 카드 안 사진에 `loading="lazy"`. 굽는 무대는 지금처럼 즉시(기본값) | 모든 사진 즉시 — 카드 13장이면 원본 사진을 한 번에 받는다 |
| 구운 이미지 | **그대로 둔다.** 인스타 내보내기 · 목록 썸네일 · 영문 페이지가 쓴다 | 굽기 폐지 — 인스타 용도가 사라진다 |
| 등장 애니메이션 | 카드는 `BlurFade` 로 감싸지 않는다 | 다른 블록처럼 감싸기 — 서버 HTML 이 `opacity:0` 으로 나가 JS 를 끈 첫 화면에서 본문이 통째로 비었다(실측). 글자를 읽히게 하려는 작업이다 |

| 3 | 본문에서 이미지 블록을 카드로 | `components/ds/post-body.tsx` | 수가 안 맞으면 이미지 그대로 |
| 4 | 기사·라이브러리 상세에서 덱 넘기기 | `app/[lang]/news/[id]` · `library/[id]` | 원문 언어 페이지만 |
| 5 | 검증 | — | HTML 에 카드 글이 실제로 있음 · 구운 이미지와 나란히 비교 · 품질 게이트 |

## 이 계획이 하지 않는 것

- 덱이 없는 2건(라이브러리)의 본문 — `/admin` 에서 사람이 문단을 써야 한다.
- 영문 페이지의 HTML 카드 — 영문 카드는 이미 구워져 있지만(`-en-NN.webp`) 영문 덱은 저장돼 있지 않다. 영문 덱을 함께 저장하면 같은 방식으로 그릴 수 있다.
- 구조화 데이터에 `articleBody` 넣기 — 본문이 HTML 로 생기면 우선 그것으로 충분하다.
